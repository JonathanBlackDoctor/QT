## 복구 설계

00:05 1차, 00:20 첫 복구를 유지하고 00:35부터 04:50까지 15분 간격 슬롯을 추가한다. 파이프라인 또는 준비 상태 검사 코드를 main에 수정하면 push 이벤트로 즉시 누락분을 점검한다. workflow_dispatch 수동 실행도 유지한다.

매 실행은 KST 달력 날짜의 문서와 인덱스를 먼저 검사한다. 정상 문서와 실제 GitHub Pages 게시본까지 일치하면 모델 호출과 배포를 건너뛴다. 문서는 정상인데 게시본이 없거나 다르면 모델을 재호출하지 않고 배포만 복구한다. 00:20 첫 복구 슬롯에서는 기존 BibleProject/Reading Jesus 보완 재시도를 유지하며, 이후의 일반 복구는 이미 정상인 해설을 반복 생성하지 않는다.

부가 관점 수집은 별도 3분 제한과 비차단 단계로 두되, 기존 출처/콘텐츠 검증은 그대로 통과해야 게시한다. 본문을 검증하지 못한 실패 기록은 보관·배포하더라도 최종 준비 검사가 실패하므로 workflow success로 위장되지 않는다. 배포 후에도 공개 JSON과 인덱스를 검사하며, 짧은 전파 지연에는 제한된 재확인을 한다.

이 방식은 예약 미시작에 대한 추가 기회와 즉시 복구 경로를 제공하지만 GitHub 스케줄러 자체를 고치거나 실행 시각을 보증하지는 않는다. 예약 슬롯 전체가 전달되지 않는 장애까지 분리하려면 GitHub 외부의 독립 스케줄러가 필요하다. 이 변경에는 새 외부 서비스 계정이나 스케줄러를 연결하지 않았다.

기본 날짜의 기록이 없으면 그 이전의 가장 가까운 날짜를 표시하고 준비 중 안내를 남긴다. 미래 날짜만 있을 때는 준비 중 화면을 표시한다. 열린 기본 홈 탭은 04:00 타이머와 focus/visibilitychange/pageshow로 전환을 확인한다. 명시적으로 날짜를 선택한 링크는 자동 전환하지 않는다.
